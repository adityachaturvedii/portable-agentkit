All canaries were created under disposable temporary roots; none contained real credentials. The trusted Python probe directly attempted operations; the parent independently checked credential/common-metadata integrity and marker-file existence. The only network target was a parent-owned loopback listener. Reports retain every failed argument experiment: the first two Codex read-only invocations lacked the newly required named profile. Corrected named profiles were explicitly restricted and were never an unrestricted fallback.

The probe deliberately injects a **fake** secret variable to show that neither native Seatbelt nor the shared wrapper clears environment variables. Adapter tests independently show the allowlist excludes API keys and loader/provider overrides. This protects inheritance, not files readable to the CLI itself, Keychain services, or sensitive files accessed by a future tool.

Process-group cleanup tests kill TERM-resistant children on timeout/cancellation and after normal parent exit. This is lifecycle management, not a hostile-process boundary: a detached session, remote request, pre-existing service or crash can outlive it. Group disappearance must not be promoted to remote cancellation confirmation.

Official documentation provides context, not substituted evidence: [Codex configuration](https://learn.chatgpt.com/docs/config-file/config-reference) and [Claude sandboxing](https://code.claude.com/docs/en/sandboxing). Claude's native shell sandbox and built-in tools use different controls. Browser/computer/MCP/credential paths require separate tests; none is approved by this matrix.

**Supported scope:** offline foundation, read-only diagnosis, fixture transport and a narrow authorized Claude model-only smoke on this host. **Unsupported:** tool-enabled managed execution, unattended untrusted work, comprehensive credential isolation and universal egress isolation. Codex's guarded live task remains blocked. No release claim extends beyond these observations.
