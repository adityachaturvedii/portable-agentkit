Build a polished browser-based Breakout game. It should support keyboard and touch controls, responsive desktop and mobile layouts, scoring, lives, start, pause/resume, restart, and clear win/lose states. Include concise instructions and readable, accessible controls. Make it visually cohesive and enjoyable to play. Run locally with no account, backend, external service, or deployment.

Use only the controller-provided dependency-free static project. Keep the game deterministic enough for the protected mechanics contract. Expose the same test-only API as `module.exports` in Node and `globalThis.BreakoutTest` in a browser: `createState(options)`, `start(state)`, `togglePause(state)`, `restart(state)`, and `step(state, deltaSeconds, input)`. State must expose `width`, `height`, `status`, `score`, `lives`, `paddle`, `ball`, and `bricks`; bricks expose geometry, `alive`, and `points`. The visible game must use the same mechanics API. This interface exists for independent acceptance and must not bypass the playable UI.
