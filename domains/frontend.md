# Frontend

Trigger: A user-visible web flow, layout or accessibility change.

1. Specify critical user flows and use an approved disposable browser context and synthetic data. Record target build, viewport and browser version.

2. Check keyboard navigation, labels/focus, error/loading/empty states and relevant responsive widths. Include actual before/after artifacts for failed interactions.

3. Separate static source inspection from browser observation and full accessibility assessment. Do not claim a user-flow pass from HTML presence alone.

Stop: Browser/build identity unavailable or action would affect a real account without authorization.

Output: add the relevant checks, identities and evidence to the parent skill handoff; record missing capabilities in limitations. This procedure supplies requirements, not an installed tool or tested execution adapter.
